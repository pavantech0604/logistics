# Animation implementation review

1. **Application audit:** React 19, TypeScript, Vite, Tailwind, Framer Motion and React Three Fiber. Routes cover home, products, freight calculator, process, about and contact. Shared domain components retain their existing data and callbacks. The existing hero includes a lazy WebGL terminal and an SVG fallback.
2. **Main problems:** Dense product and certification grids, long corporate paragraphs, repetitive flat cards and scattered animation settings. Inputs, route tables and forms need stable surfaces rather than continuous movement.
3. **Direction:** Preserve both existing color themes. Add measured perspective and section-specific logistics geometry. Reuse existing reveal and scene systems; do not add dependencies, full-screen canvases or fake statistics.
4. **Section behavior:** Hero retains its existing scene. Tracking uses raised selected nodes and depth transitions. Corporate imagery gets pointer tilt. Products and certifications get spring-smoothed card tilt. Freight adds an isometric stack based on the real container estimate, capped at eight visible units with an overflow count. Process selection gets a subtle depth transition. Feature cards and the corridor map get pointer depth. Contact gets a decorative object while its form stays static. Each home-page section receives a decorative CSS 3D logistics object that pauses offscreen or when the document is hidden.
5. **Changed files:** `src/main.tsx`, `src/pages/HomePage.tsx`, `src/components/ui/Card.tsx`, `src/components/ui/ReducedMotion.test.tsx`, and domain components `ProductCard.tsx`, `QualityCertifications.tsx`, `TrackingPreview.tsx`, `ExportProcessTimeline.tsx`, `FreightCalculator.tsx`, `RouteNetwork.tsx`. New files: `src/components/ui/Depth.tsx`, `src/components/ui/depthMotionConfig.ts`, `src/components/domain/CargoDepth.tsx`, `src/depth-motion.css`, and this review. No color-theme files were edited.
6. **Implementation:** `TiltSurface` uses motion values and springs without React state updates on pointer movement. `SectionObject` builds six CSS faces with an icon representing the section. `CargoDepth` renders the current estimate without changing calculation logic. Shared `Card` opts into tilt through `hoverEffect`; product cards and certificates use the wrapper directly.
7. **Accessibility:** Decorative geometry is aria-hidden and cannot intercept pointer events. Reduced motion disables looping geometry, tilt and entrance transforms. Keyboard focus keeps surfaces flat. Native buttons, links and existing modal controls remain intact. The new test checks focus, action availability, disabled decorative loops and the bounded cargo visualization.
8. **Performance:** No new dependencies or WebGL contexts. Observer and visibility listeners are cleaned up. Only visible section objects animate. The freight visualization has bounded geometry. Animations use transforms; no layout animation or scroll hijacking was added. This is a code-level performance review, not a measured FPS benchmark.
9. **Responsive behavior:** Pointer tilt is disabled for coarse pointers and non-hover devices. Section objects shrink below 900px and sit outside text areas. Existing responsive grids and horizontal route-table scrolling remain. The current browser ignored requested viewport overrides, so a fresh mobile/tablet visual check remains unverified. Desktop inspection showed no horizontal overflow and product details opened successfully.
10. **Validation:** Production build passed. All 16 tests passed. Lint has only the pre-existing fast-refresh warning in Toast.tsx. Commands: `npm run dev`, `npm run build`, `npm run test`, `npm run lint`. Before deployment, inspect mobile/tablet layouts and profile performance on target devices.
11. **Adjustments:** Change `DEPTH_MOTION.tilt`, `perspective`, `stiffness` and `damping` in `depthMotionConfig.ts` to tune pointer motion. Adjust `--depth-cycle` and the `depth-float` keyframe in `depth-motion.css` to tune decorative movement. The existing routes, content, theme palette and business logic are preserved.
